# Output Pacing and Flush Boundary

Task 8 hardens the existing WebSocket `PacedWriter`; there is no second pacing engine. The transport retains protobuf encoding and socket writes. Core owns provider-neutral speaking transition types and the small concurrency-safe `SpeakingTracker`.

## Queue and pacing

Enqueue copies the frame and sample bytes, derives a single normalized duration when the producer omits one, and stores that duration with the queue entry. Admission checks frame-count, byte, and media-duration budgets before mutation. Overflow returns both `ErrQueueBufferFull` and the V1-compatible `ErrSlowClient`; retained accounting and a matching pending final marker are unchanged, so a retry can still become turn-final. Non-positive budget values are normalized to bounded defaults without changing the public constructor. Queue locks are not held during pacing waits, encoding, socket writes, or callbacks.

The default queue remains 4,800 bytes / 100 ms at 24-kHz PCM16 mono and is additionally bounded to 64 frames, including empty frames. The queue stores at most 64 pending whole-turn final markers. A marker-limit failure is explicit and fail-closed.

## Whole-turn finality and speaking

`OutputAudioFrame.IsFinal` continues to mean “last audio chunk of this synthesis unit.” `TurnFinal` means “last output for the whole assistant turn.” When LLM completion is known before the last synthesis unit is emitted, Google, xAI, and the deterministic fake copy `SynthesisUnitFrame.IsFinal` onto the last audio chunk; xAI also emits an empty final frame when a final unit contains no audio. When a punctuation-aligned unit was already streamed, `AssistantContextProcessor` emits an ordered `OutputTurnFinalFrame`. The pacer reconciles that marker whether it arrives before admission, while the unit is queued, selected for pacing, in a transport write, or just after successful completion. A late marker schedules an abortable drain at the recorded media end instead of blocking the transport processor or stopping early; empty unit-finals enter the same completed lifecycle. Uninterruptible final drains survive flush and retain their media clock.

Finality-participating external producers must supply nonzero `UnitID` values that are strictly increasing across the paced session (all chunks of one unit share its ID). The core assistant context now supplies this session-global sequence. The pacer rejects nonmonotonic final identities, keeps pending/completed state bounded, and retires terminal IDs through a monotonic high-water mark. This makes old duplicate markers permanent no-ops without an unbounded terminal-ID set.

Speaking starts only after a successful non-empty socket write. It does not start on enqueue, `TTSStarted`, empty output, encoding failure, stale output, or a canceled write. It stops once on the paced whole-turn drain, flush/interruption, fatal write failure, or close. Unit-final frames do not stop speaking, so multi-unit turns do not flicker. `SpeakingStateFrame` is provider-neutral and maps directly to RTVI `bot-started-speaking` / `bot-stopped-speaking`. These events describe server output state, not client playback acknowledgement.

## Flush barrier

A flush removes queued interruptible output through its target generation and aborts targeted work that is still selected or pacing. Admission into the transport write is atomic with the final generation/drop/closed check. Once a write is transport-bound, the default real-WebSocket path waits for the writer wrapper to return and acknowledges only after quiescence; it does not cancel coder/websocket's write context because canceling an actual in-progress coder write closes the connection. The integration test holds the wrapper after coder `Write` has returned, proving wrapper-level barrier waiting and same-connection reuse; it does not claim to cancel or recover an actual in-progress coder write. An explicitly configured recoverable writer may opt into cancellation. Repeated and overlapping flushes retain independent callbacks for their requested generation. A late physical write return is fenced before metrics, speaking state, or write completion. A stale or no-op flush cannot stop newer-generation speaking or reset its retained pacing clock.

Explicitly uninterruptible output and its final drain are retained in place, even when their generation is older than the active fence. New-generation output appends after retained media and is paced normally. Run cancellation and close clear queued accounting and abort any scheduled late drain while balancing speaking state exactly once. The timeout path is tested separately with an unresponsive writer; the pacer closes itself before returning `ErrSlowClient`, and the connection adapter never emits a successful flush acknowledgement.

The server guarantee ends at bytes already accepted by the socket. The pinned unmodified browser client still cannot clear buffered playback; `docs/compatibility/playback-clear-decision.json` therefore remains unresolved and is not a pass.
