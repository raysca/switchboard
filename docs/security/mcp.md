# MCP transport and security policy

The Server MCP package owns MCP protocol types and converts them into server storage records and API DTOs. Core and provider ToolLoop contracts contain no MCP types. Remote tools are identified by `(MCPServerID, remote tool name)` and every discovery refresh creates a new immutable snapshot with stable canonical schema and discovery hashes.

## Supported transport and authentication

Task 17 supports remote Streamable HTTP only. A configured endpoint must be an HTTPS URL with a host, no embedded URL credentials, and no query parameters. Rejecting queries prevents access tokens from being persisted as part of the endpoint; integrations must use `auth_env` instead. Local/process (`stdio`) is explicitly rejected; this avoids turning management access into arbitrary executable and filesystem access. Enabling it later requires a separate admin/config allowlist, process sandbox, working-directory policy, and executable provenance review.

Authentication is by `auth_env`: the name of a secret, resolved at operation time (`mcp.ResolverTokens`) and attached by the MCP HTTP client as a Bearer header. The name is an `MCP_TOKEN_[A-Z0-9_]{1,48}` environment variable, or a lower-case secret from the secrets directory or the encrypted store ([credentials.md](credentials.md#tool-and-mcp-secrets)). The name form is the security boundary: a management caller who can create MCP servers can choose any `auth_env`, and the value is sent to the MCP endpoint they configure, so a name must not be able to select provider keys or the management API key. The resolver refuses to read any environment variable outside the prefix (and `HTTP_TOKEN_` variables, which belong to HTTP tools), and ignores empty values or values containing whitespace or control characters. A secrets directory is therefore exposed to anyone who can create MCP servers: use a dedicated one. The token is never persisted, returned by management APIs (views show only `auth_env` and `auth_env_set`), or included in trace attributes or service errors; the variable name is safe to record. Rotating an environment variable is a redeploy with the new value; a directory or stored secret is rotated in place. The name stays. A server whose variable is unset or empty makes its tool dependencies `auth_env_missing`, and readiness names only the variable. This adapter does not implement OAuth discovery/refresh or arbitrary custom headers.

The HTTPS policy rejects URL user-info and cleartext HTTP. The same public-egress predicate is applied to endpoint resolution and again to every DNS answer immediately before dialing; if any answer is private or special-use, the request is rejected, and successful dials pin one of the checked addresses. Denied ranges include private, loopback, link-local, CGNAT, documentation, benchmarking, protocol-assignment, deprecated site-local, multicast, and other non-public ranges. Redirect following and ambient proxy routing are disabled to prevent credential forwarding across destinations. Deployments may inject a stricter `DestinationPolicy`; the default does not allow internal MCP destinations.

**Development and tests: `mcp.allow_local_http`.** With this setting the server also accepts `http` or `https` endpoints on loopback (`127.0.0.0/8`, `::1`, and a host name whose every address is loopback), so local test MCP servers are reachable. It is checked in all three places the HTTPS policy is: when an endpoint is registered, before each request, and again for every DNS answer at dial time, so a name that resolves to a private or metadata address is still refused. Nothing else is loosened: private LAN ranges, link-local and metadata addresses, `0.0.0.0`, embedded credentials and query strings stay refused, and plain HTTP to a public host is refused. `config/development.yaml` enables it; the production profile refuses to start with it (`mcp.allow_local_http is for development and tests`).

## Resource bounds and execution

Each remote operation receives a context deadline (`mcp.timeout`, 15 seconds by default, capped at two minutes). When a call ends early (timeout or barge-in) the client closes the call's request, and the session teardown (the DELETE and the SDK's cancellation notice) runs on its own 300 ms budget detached from the call, so an unresponsive server cannot hold teardown for seconds. Whether a remote server stops the tool it was running then depends on that server: the official SDK server stops it only when the session ends. Cancellation flows into the official SDK client. Tool catalogs are limited to 256 entries; tool descriptions to 4 KiB; schemas to 64 KiB; test arguments to 64 KiB; and returned structured JSON to 256 KiB by default. The SDK event reader has an independent body/event bound. Schemas are resolved without loading remote `$ref` documents, so a schema cannot make the Server fetch arbitrary URLs.

The validation console and agent wrappers call the same captured-handle execution path. `CaptureTool` snapshots the selected schema and validated endpoint and resolves the token once for that session. The service checks arguments against that captured JSON Schema before sending a request, and normalizes remote failures to safe categories. Results are parsed as bounded JSON, recursively redact secret-shaped keys and occurrences of the resolved credential (including JSON-escaped credential spellings), then are reserialized and size-checked. Tool failures reach the model as a category (`invalid_arguments`, `timeout`, `unavailable`, `result_too_large`, `tool_error`, `cancelled`). For `tool_error` the model also gets the tool's own error text: control characters removed, the credential redacted, at most 512 bytes. That text is remote data and is no more trusted than a successful result, which also reaches the model. Traces and logs carry the category only, never the message. Try it shows the message to the management caller. Traces contain an opaque execution ID and sanitized server/tool identity, duration, and tool counts; arguments, results, endpoints, and credentials are excluded. Spans retain the caller's parent context.

Captured bearer tokens remain only in the session's in-memory wrapper and are released when that session drains. Changing the secret (an `MCP_TOKEN_*` variable needs a restart) or deleting the server prevents future captures but does not revoke the copied bearer token from an already active session; an operator requiring immediate revocation must end those sessions, and the upstream MCP service can also revoke the token. No token bytes are included in `runtime_snapshot_json`, API DTOs, history, or logs.

Schema preflight accepts an omitted dialect or exactly the dialect spellings supported by the pinned `jsonschema-go` v0.4.3 validator: `https://json-schema.org/draft/2020-12/schema`, `http://json-schema.org/draft-07/schema#`, and `https://json-schema.org/draft-07/schema#`. Similar URIs with missing or added fragments are rejected at discovery; accepted dialects are exercised through execution with `{}` in regression tests.

Only root-local JSON Pointer `$ref` references are supported. The only permitted dollar-prefixed keys are `$schema`, `$ref`, `$defs`, and `$comment`; `$dynamicRef`, `$recursiveRef`, anchors, resource `$id` scopes, vocabulary declarations, and alternate dollar-key spellings are rejected. This restriction applies throughout the supplied JSON, including annotations. References must point to object or boolean schemas. Every reference cycle is rejected, including recursive schemas that could otherwise validate finite arguments safely.

Preflight limits the stored JSON tree to 4,096 values, 128 references, and depth 64. It also charges every reference occurrence and combinator branch against a 16,384-value expanded-graph budget and caps expanded depth at 64. Shared targets are charged again at each use, so a small acyclic graph with exponential expansion is rejected before validator resolution. Definitions and annotations are counted conservatively even when validation would not visit them. The check memoizes bounded costs and does not expand the graph itself. Decoding uses the exact JSON tree inspected by preflight; the validator's canonical schema is checked again before resolution to catch keyword alias merging. This intentionally excludes some otherwise valid schemas and remote schema catalogs. The limits bound schema work; context deadlines do not interrupt the synchronous validator mid-call.

## Validation state

The persisted state is one of `not_validated`, `healthy`, `authentication_failed`, `connection_failed`, `discovery_failed`, `tool_schema_invalid`, or `disabled`. Typed authentication failures take priority, followed by connection/initialization failures and cancellation/deadline failures; these remain `connection_failed` during discovery. Other list failures use `discovery_failed`. The API reports only these values and does not return remote error bodies. A failed refresh never replaces the last successful immutable discovery. Discovery and execution record duration before ending the span, including failures, so asynchronous exporters receive it.

`mcp.Handler(service)` (`server/mcp/http.go`) serves the `/api/v1/mcp-servers` routes and takes no auth object: it does no authentication itself. Its only protection is the mount: `Server.EnableManagement` (`server/management.go`) builds the service from the storage, the environment token resolver and the configured timeout, and installs the handler behind `handleAPI` (`server/api_routes.go`), which refuses with 503 when no management key is set, authenticates every request with the management key and propagates the server-generated request ID. No public voice listener mounts it.

## SDK choice and adapter boundary

The Server uses the official maintained `github.com/modelcontextprotocol/go-sdk` at v1.8.0. The official SDK repository identifies `mcp` as its primary client/server API and lists v1.7.0+ as supporting protocol version 2026-07-28; v1.8.0 is the current stable SDK selected when Task 17 was implemented. v1.8.0 requires Go 1.25, below this module's Go 1.27.1 baseline. The Server-owned `RemoteClient` adapter isolates SDK churn and keeps MCP types out of core and public storage/API contracts.

The compatibility cost is the SDK's protocol implementation and Go-version dependency; upgrading SDK versions is an explicit Server integration change. The current adapter opens a request-scoped Streamable HTTP session for discovery and tool execution and intentionally does not expose server-initiated notifications or local process management.

## Testing MCP integration

`cmd/mcptest` (package `server/mcp/mcptest`) serves MCP servers with known behaviour on loopback, used by the Go tests, the browser suite and `make dev`; `make mcp-test` runs it alone on `127.0.0.1:18765` with a black hole on `:18766`.

| Path | Auth | Behaviour |
|---|---|---|
| `/ok` | bearer token (`-token`, `MCPTEST_TOKEN`, default `test-token`) | `lookup_order(order_id)` and `echo(text)` |
| `/open` | none | the same tools |
| `/fail/tools` | none | `tool_error` (tool error result), `protocol_error` (JSON-RPC error), `drop` (closes the connection), `too_big` (result over the size limit) |
| `/fail/auth` | always 401 | |
| `/fail/list` | none | `tools/list` fails |
| `/slow` | none | `slow_lookup(delay_ms)` answers after the delay (at most 120 s) |
| black hole | none | accepts connections and never answers |

`GET /_record` returns what each server received (path, JSON-RPC method, tool, arguments, whether a token was absent, matched or mismatched, and whether the client abandoned the call); it never stores a token. Unreachable cases need no server: a closed loopback port, or a `.invalid` host name (refused when it is registered).
