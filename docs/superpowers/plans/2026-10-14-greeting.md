# Greeting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any step of a flow can have an optional `greeting`: exact words the agent says when the step takes the call (the start step when the call connects, any other step when a route hands the call to it), interruptible, recorded as a normal turn, set from the step's Basics tab.

**Architecture:** A new core method `AssistantContextProcessor.Say(text)` feeds fixed text through the assistant path (the same one model replies use), so it is split into units, spoken, committed to history on delivery, recorded as a turn, and interruptible with the partial-turn rule. The server calls it (1) once after the session starts, for the start step's greeting, and (2) from `Handoff.Greet` after an idle flip, for the target step's greeting, replacing the model-written transfer greeting (the previous agent's note is kept as a context-only history message). A turn flip (the caller spoke first) plays no greeting. Config: `greeting` on the step's config, validated, any step, flat form at top level. UI: a Greeting field in the step Basics tab and in First run.

**Tech Stack:** Go (`core/`, `server/flow`, `server/`), React 19 + TypeScript + vitest, Playwright echo suite.

**Spec:** `docs/superpowers/specs/2026-10-14-greeting-design.md` (approved). Console spec row S5.

## Global Constraints

- `core/` stays server-agnostic and every `core/` addition is consumed by `server/` (AGENTS.md): `Say` is used by the opening and the handoff greeting.
- Every goroutine ends with its session (`session.Go`); nothing unbounded: one greeting job per call opening and one per idle handoff (handoffs already capped at 10 per call). No lock is held across `Say` (it only queues).
- Greeting limits: trimmed; at most 500 **bytes**; no control characters except `\n` and `\t`; wrong type rejected; whitespace-only counts as empty.
- Schema stays version 2 and additive; a config without `greeting` behaves exactly as before.
- Monotonic time only; wrap errors with `%w`; all Go passes `go test -race ./...`; `gofmt -w .`; conventional commits; independent Opus review at the end.
- Secrets never involved; a greeting is operator-authored text stored like any assistant text (existing redaction and retention apply).

## Review Focus

1. **Barge-in on a greeting** (the caller talks over it, including in the first second of a call): the greeting stops, only the heard part enters history, the turn is marked interrupted, and the caller's words get a normal reply. Pinned in Task 1 and Task 3.
2. **The handoff greeting is spoken at the new generation and in the new voice.** A greeting spoken at the old generation would be discarded as stale; one spoken before the TTS swap would use the old step's voice. Pinned in Task 4.
3. **The previous agent's note is never lost** when a step has a greeting: it is in the history, before the greeting, and not shown to the caller. Pinned in Task 4.
4. **A turn flip plays no greeting, and a return to the start step does not replay the opening greeting.** Pinned in Task 4.
5. **A failing greeting never fails the call or a handoff**, and a flow without greetings is byte-for-byte today's behavior (no extra turn, no extra history message). Pinned in Task 3 and Task 4.

## Rulings made while planning (re-read before Task 1)

1. **`voice_greeting_failed_total` counts greetings that could not be queued** (session closing, injection refused). A TTS failure after queueing is already counted by the existing TTS error metrics and `UnitFailureReporter`; this plan does not duplicate it. Cost if wrong: a spoken-but-failed greeting shows in the TTS error metrics, not the greeting counter.
2. **The start step's greeting plays once at call start** and never again; the model-written transfer greeting is what a return to the start step gets (spec).
3. **The unbuilt-voice case needs no special code:** a step whose TTS cannot be built already fails the handoff before any greeting; the greeting is only reached after a successful flip.
4. **The opening hook** is a pipeline-builder callback (`CallSpec.OnGreeter func(say func(string) error)`, the pattern of `OnInjector`), because the builder creates the assistant processor; the server queues the opening greeting when the session starts via a debug subscription to `core.DebugSessionStarted` (the observer already uses this). If the first implementation shows a simpler reliable hook, rule and ledger it.

    ```go
    greeting := ""
    if g := lastGreeting.Load(); g != nil {
        greeting = *g
    }
    // the start step's greeting is the call opening only: a return to it gets the model's transfer greeting
    if greeting != "" && nodeID != call.Flow.Start && asstSay != nil {

            if err := ctxPool.AddMessage(core.Message{Role: core.RoleUser, Content: transferNote(name, note)}); err != nil {
                return err
            }
        }
        queueGreeting(asstSay, greeting, &metrics.GreetingFailedTotal, logger, sessionID) // a Say error is counted and logged, never returned
        return nil
    }
    return ctxPool.AddMessage(core.Message{Role: core.RoleUser, Content: transferGreeting(name, note)}) // today's behaviour
    ```

  - Neutralise the note exactly as `transferGreeting` does (`neutralizeNoteMarker`).
