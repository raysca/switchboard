# First Run and the Empty and Error States Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the plain two-step Onboarding page with the Switchboard **First run** (canvas board 1): a four-step guided path (voice stack → flow → test call → connect) with a progress list, built only on what the server can do today; and bring the empty, loading, error and not-connected states (canvas board 0) to the canvas: errors that say what happened, that live calls are not affected, and the one next step; skeleton loading rows; the dark management-key strip; the dashboard's "two steps to your first call" checklist.

**Architecture:** A pure module (`firstRun.ts`) turns `GET /providers` into one-provider voice stacks with the **catalog's** defaults and builds the flow to create. `OnboardingView` is a stepper whose step lives in the URL (`?step=` and `?flow=`), so a reload or a shared link resumes. Step 3 embeds the existing `FlowVoiceTest`; step 4 prints the token request and client snippet with the real flow id. The shared `ErrorState` and `LoadingState` gain the canvas's details, and every read failure uses them. The Dashboard gets a setup checklist. No server or API change.

**Tech Stack:** React 19, TypeScript 7, react-router 7, @tanstack/react-query 5, vitest 5 + Testing Library, Playwright (`e2e/tests-flows`).

**Spec:** `docs/superpowers/specs/2026-10-12-switchboard-console-design.md` (Section 3 boards 0–1, Section 5 S3/S5; this is plan 7, the last). Visual rules: `docs/superpowers/specs/2026-10-12-ui-switchboard-design.md`. Canvas boards `States.dc.html` (0) and `Onboarding.dc.html` (1).

## What the server supports today (and so what First run can and cannot do)

- **No key paste (S3).** The server reads provider keys from its environment and has no endpoint to store one. The canvas's "Paste key → saved to the sealed keyring" is replaced by naming the variable to set on the server (`ProviderStatus.env`, `services[*].missing_env`). Nothing on these pages may collect or send a secret.
- **No greeting field (S5).** The canvas's "First thing it says" has nowhere to go in the flow config, so it is left out.
- **No drafts (S1).** `POST /flows` publishes v1 at once, and only a ready, enabled flow can take a test call. So "Create and call it" creates the flow as **v1, enabled**; the canvas's "Saved as v1 draft / Not published yet / nothing is live yet" is not true here and must not appear. (No caller can reach it without a voice token from the management API, which is what step 4 explains.)
- **Voice stacks.** One provider can run all three stages when its catalog lists `stt`, `llm` and `tts`. The catalog marks defaults (`models[].default`, `voices[].default`, `languages[].default`). Mixed stacks are not offered here (the flow editor does that), so the canvas's "Fastest replies" mixed stack is left out.
- **A test call** runs the published version over the same WebSocket path callers use (`FlowVoiceTest`); it reports barge-ins but not reply times (S9), so the canvas's "first reply 612 ms" chips are left out.
- **The management API errors** carry `status`, `code`, `message`, `requestId` (`ApiError`). They never affect live calls: that is true of every read endpoint the console uses.

## Global Constraints

- UI copy says Flow / Step / Route / Call. API names stay as they are now (`FlowDTO`, `client.getFlows/createFlow`, `client.issueVoiceToken({ principal, flow_id })`, `/api/v1/flows`, query keys `["flows"]`, `["providers"]`).
- **Never show or accept a secret.** No password or key input on these pages (the only `input` types are text, textarea, select, and radios). The management key never appears in "Copy details", in snippets, or in the URL. The existing guard in `OnboardingView.test.tsx` ("no credential form") stays.
- Colours only through tokens; no hex or `rgb(` in TSX or below `/* end tokens */`; add every new TSX file to `CONVERTED` in `ui/src/test/noHardcodedColors.test.ts`. Radius is `var(--radius)`, `50%` or `999px`; no drop shadows (the canvas call halo is left out); only weights 450/600/800; no opacity-faded text; sentence-case labels; 44px touch targets; the global focus ring. Lamp amber is only for a live call (the test call in step 3 may use it).
- Copy is honest: nothing says "draft", "not published", "nothing is live yet", "sealed keyring", "stopped in N ms" or a latency the server does not report. The reassurance "Live calls are not affected" appears only on read failures of the management API, never on failed actions (publish, delete, connect).
- Defaults come from the provider catalog, never from hard-coded model names.
- Keep working: `/onboarding` route; the `Management key` label, `Connect` button and `Key in memory` text (every suite connects through them); `FlowVoiceTest`'s test ids; all existing `ErrorState` titles and the button name `Try again`.
- Gate for every task: `cd ui && npx vitest run && npx tsc --noEmit`; after Tasks 1, 2 and 6 also `make e2e-fake`.
- Commits are conventional (`feat(ui): …`) and end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A catalog the plan did not anticipate.** A provider that lists only some services, a service with no default entry, one with no models, a catalog with no provider ready. Expect: only providers that cover all three stages are offered; a missing default falls back to the first entry; with none ready, step 1 says which variables to set and Continue stays off; nothing throws. Pinned in Tasks 3 and 4.
2. **Resuming and deep links.** `?step=` garbage, `?step=3` with no or an unknown `flow`, a flow archived in another tab, a reload on step 3 or 4. Expect: a sensible earlier step, never a blank page or a crash. Pinned in Tasks 4 and 5.
3. **No secret anywhere.** No key field; "Copy details" and the snippets exclude the management key and any `Authorization` value; the URL never holds a key. Pinned in Tasks 1 and 5.
4. **Honest wording.** The created flow is live as v1; the connect step says that a caller needs a voice token minted by the backend; the checklist and empty states claim only what the data shows. Pinned in Tasks 4, 5 and 6.
5. **Failure of the helpers themselves.** The clipboard may be missing or refuse; a create call may fail; the provider or flow list may fail while the other loads. Expect an inline message and the page still usable. Pinned in Tasks 1 and 5.

```tsx
export function LoadingState({ label = "Loading", skeleton }: { label?: string; skeleton?: number }) {
  if (!skeleton) {
    return (
      <p className="loading" role="status">
        {label}…
      </p>
    );
  }
  return (
    <div className="skeleton" aria-busy="true">
      <p className="visually-hidden" role="status">
        {label}…
      </p>
      {Array.from({ length: skeleton }, (_, i) => (
        <div key={i} className="skeleton__row" aria-hidden="true">
          <span style={{ width: `${55 + ((i * 13) % 35)}%` }} />
          <span style={{ width: `${45 + ((i * 17) % 40)}%` }} />
          <span style={{ width: `${60 + ((i * 7) % 30)}%` }} />
        </div>
      ))}
    </div>
  );
}
export function ErrorState({
  error,
  onRetry,
  title = "Request failed",
  reassure = false,
}: {
  error: ApiError;
  onRetry?: () => void;
  title?: string;
  /** A read failure of the management API: say that live calls are not affected. */
  reassure?: boolean;
}) {
  const [copied, setCopied] = useState<"idle" | "yes" | "no">("idle");
  const hasDetails = error.status > 0 || !!error.code || !!error.requestId;
  const copy = async () => {
    const text = `status ${error.status} ${error.code}\nrequest ${error.requestId}\n${error.message}`;
    try {
      await navigator.clipboard.writeText(text);
      setCopied("yes");
    } catch {
      setCopied("no");
    }
  };
  return (
    <section className="message-panel message-panel--error" role="alert">
      <h2>{title}</h2>
      <p>{error.message}</p>
      {reassure && <p>Live calls are not affected. This only stops the console from reading.</p>}
      {hasDetails && (
        <dl className="error-details">
          {error.status > 0 && (
            <>
              <dt>status</dt>
              <dd>
                {error.status} {error.code}
              </dd>
            </>
          )}
          {error.requestId && (
            <>
              <dt>request</dt>
              <dd>{error.requestId}</dd>
            </>
          )}
        </dl>
      )}
      <div className="row">
        {onRetry && <button onClick={onRetry}>Try again</button>}
        {hasDetails && (
          <button type="button" className="action-button-small" onClick={() => void copy()}>
            Copy details
          </button>
        )}
        {copied === "yes" && <span className="subtext">Copied</span>}
        {copied === "no" && <span className="subtext">Could not copy. Select the details and copy them yourself.</span>}
      </div>
    </section>
  );
}
```

import type { CreateFlowInput, ProviderStatus } from "../../api/client";
import { missingEnv } from "../providers/providerStats";

export type Entry = { id: string; label: string; default?: boolean };

export type Stack = {
  provider: ProviderStatus;
  stt: { model: string; label: string; language?: string };
  llm: { model: string; label: string };
  tts: { voice: string; label: string; voices: Entry[] };
  /** Every service of the provider can run now. */
  ready: boolean;
  /** What is still to set on the server when it is not ready. */
  missing: string[];
};

export const DEFAULT_JOB = "Answer calls politely. Greet the caller, find out what they need, and answer in one or two short sentences. If you cannot help, take a message with their name and number.";

const pick = (entries: Entry[] | undefined): Entry | undefined => entries?.find((e) => e.default) ?? entries?.[0];

/** One provider for all three stages, with the catalog's defaults. Mixing providers is done in the flow editor. */
export function stacksFrom(providers: ProviderStatus[]): Stack[] {
  const stacks: Stack[] = [];
  for (const provider of providers) {
    const { stt, llm, tts } = provider.services;
    const sttModel = pick(stt?.models);
    const llmModel = pick(llm?.models);
    const voice = pick(tts?.voices);
    if (!stt || !llm || !tts || !sttModel || !llmModel || !voice) continue;
    stacks.push({
      provider,
      stt: { model: sttModel.id, label: sttModel.label, language: pick(stt.languages)?.id },
      llm: { model: llmModel.id, label: llmModel.label },
      tts: { voice: voice.id, label: voice.label, voices: tts.voices ?? [] },
      ready: stt.available && llm.available && tts.available,
      missing: missingEnv(provider),
    });
  }
  return stacks.sort((a, b) => Number(b.ready) - Number(a.ready) || a.provider.display_name.localeCompare(b.provider.display_name));
}

export function flowFor(stack: Stack, input: { name: string; job: string; voice: string }): CreateFlowInput {
  const provider = stack.provider.id;
  const voice = stack.tts.voices.some((v) => v.id === input.voice) ? input.voice : stack.tts.voice;
  return {
    name: input.name.trim(),
    description: "",
    enabled: true,
    config: {
      stt: { provider, model: stack.stt.model, ...(stack.stt.language ? { language: stack.stt.language } : {}) },
      llm: { provider, model: stack.llm.model, system_prompt: input.job.trim() },
      tts: { provider, voice },
    },
  };
}

/** A code block with a Copy button. The clipboard may be missing or refuse: say so. */
function Snippet({ label, title, text }: { label: string; title: string; text: string }) {
  const [copied, setCopied] = useState<"idle" | "yes" | "no">("idle");
  const copy = async () => {
    try {
      await navigator.clipboard.writeText(text);
      setCopied("yes");
    } catch {
      setCopied("no");
    }
  };
  return (
    <figure className="snippet" aria-label={label}>
      <figcaption>
        <span>{title}</span>
        <button type="button" className="action-button-small" onClick={() => void copy()}>
          Copy
        </button>
        {copied === "yes" && <span className="subtext">Copied</span>}
        {copied === "no" && <span className="subtext">Could not copy. Select the text and copy it yourself.</span>}
      </figcaption>
      <pre>
        <code>{text}</code>
      </pre>
    </figure>
  );
}

import { test, expect, PROVIDER } from "../lib/flows-stack";

// First run end to end on a fresh stack: choose the stack, create the flow, call it, read the connect step.

test("first run: stack, flow, test call, connect", async ({ page, stack }) => {

  test.skip(existing.length > 0, "first run needs a stack with no flows yet");
  await connectAdmin(page, stack);
  await page.goto(`${stack.uiUrl}/onboarding`);
  await page.getByLabel("Management key").fill(stack.managementKey);

  await page.getByRole("button", { name: "Continue" }).click();

  await page.getByRole("button", { name: "Create and call it" }).click();

  await expect(page.getByRole("heading", { name: "Say hello." })).toBeVisible();

  await expect(page.getByTestId("connection-state")).toHaveText(/ready/i, { timeout: 30_000 });
