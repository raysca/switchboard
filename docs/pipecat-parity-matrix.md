# Pipecat parity matrix (P6-1)

Reference: `pipecat-impl/` @ `2967e1c09ad484076089bc88427d305fe8f79fa9`. Pipecat paths are relative to `pipecat-impl/src/pipecat/`; go-voice paths to the repo root. Scope and exclusions: `docs/plans/pipecat-parity.md`. This is the "Pipecat behavioral parity" surface of `docs/pipecat-compatibility.md`; it says nothing about RTVI client or Whisker conformance.

**Status**: `parity` = same observable behavior on the paired fixtures or tests cited; `partial` = a real subset, or same behavior with the gaps listed; `intentionally different` = deliberate other design (or a go-voice-only addition); `not planned` = not built, no plan to.

**Default**: whether a stock server runs it. `on`, `off` (and what enables it), `library only` (no config reaches it), or `n/a`. Most turn-taking rows need `turn.manager: true` first; per-agent settings live in the stored agent config, everything else is server-wide YAML (`server/config.go`).

**How rows are checked.** Rows marked *paired* run the same scripted input through Pipecat (executed from `pipecat-impl/.venv`) and go-voice; goldens are in `tools/compat/testdata/parity/`, 56 scenarios in 8 areas, 16 with a declared `intentional_difference` (each one named in a row below as `area/scenario`). `go test ./tools/compat/...` compares against the goldens without Python; `make parity-regen` re-executes Pipecat. A fixture checks one component on scripted frames, not a live call. `TestParityMatrix` fails if a path or test cited here is missing, a status or default is invalid, or a declared difference is not explained in this file.

## Known gaps and risks

Collected from the goalpulse record and re-checked against the code (G5 re-verification). Items fixed since the earlier list are removed.

- **Turn manager is opt-in, and should stay so for now.** `turn.manager` defaults off, so start/stop strategies, mute, smart-turn and LLM completion are inactive; turning it on adds about 800 ms end-of-turn with the defaults, on top of the ~0.7-0.8 s VAD stop. Server-level e2e tests exist for the analyzer, completion, idle and async-tool paths; missing: barge-in over speaking TTS plus silence end in one server-level test. Live with Google (round 2): default stop costs about +0.6 s voice-to-voice (the 700 ms timeout starts after the VAD's own ~0.74 s hangover); recommendation: not default-on until the VAD stop is configurable or the clock starts at the audio end, then re-measure.
- **Smart Turn v3.2 misjudges clips (model, not our window).** The recorded "What is two plus two?" scores incomplete and TTS fragments score complete, in Pipecat's Python too; the audio-window bug is fixed. Not recommended until evaluated on real conversational audio (`docs/benchmarks/turn-manager-live.md`).
- **`chirp_2` sends no interim results**, so `turn.min_words` gives no barge-in until its final (about 1.5 s after speech); `latest_long` has interims. A WARN and `voice_turn_min_words_no_interims_total` flag it once per call.
- **NIM reasoning-only models.** The OpenAI processor cannot pass `reasoning_effort` or `chat_template_kwargs`; reasoning models (nemotron-3-super, nemotron-3.5-lightning) have first tokens of 0.7 to 6 s or worse. Default openai/gpt-oss-20b; the catalog lists models that answer 404/410 for the account (reported as a non-retryable client error telling the operator to set the model).
- **STT breaker pattern is inconsistent**: Google and Nvidia, Cartesia and ElevenLabs STT own breakers by their own patterns; xAI STT differs (and exports no counters); xAI breakers are now per stage and quota 429s no longer open them (M3-04). Not unified; the xAI open now follows the shared rule (`WouldRefuse` gate before the dial, one Report/RecordSuccess per open, a cancelled open is not a failure).
- **`PingMaxFailures` has no YAML key** (fixed at 2 consecutive missed pings); only `limits.ping_interval` and `limits.ping_timeout` are configurable.
- **An abandoned browser tab holds its slot** until `limits.max_call_duration` unless `idle.user_timeout` is set; a tab that still answers pings is not dropped. Set `idle.user_timeout` in production (commented recommendation in `config/production.yaml`).
- **xAI TTS is unary**: one `POST /v1/tts` per sentence, so first audio waits for the whole sentence and a reply costs 2 to 5 requests (not 1); there is no streaming endpoint wired. The WebSocket TTS would fix both.
- **xAI STT ordering and drops (fixed in round 7):** `audio.done` is now written after the audio buffered before `transcript.created` (M3-02), and a connection drop mid-utterance or after `audio.done` with an open utterance raises a transcript-invalidating error so STT failover replays it (M3-09; core test `TestSTTFailoverInvalidatingDropAfterSpeechFinalCommitsOnce`). The S2 (barge-in) and S4 (mid-utterance pause) rows in `docs/benchmarks/agent-matrix.md` are stale, from before the VAD-stop correction and the round 4 fixes, and have not been re-run live.
- **Cost estimates are an upper bound, actuals are measured**: live harnesses cap on measured provider requests (`voice_provider_requests_total`; Google LLM in Vertex mode is not on the shared pool and not counted there). The estimate formulas are calibrated on one xAI run and should be refreshed from the est-vs-actual table.
- **Real-provider coverage**: Google, Nvidia and xAI were run live (small n); Cartesia, ElevenLabs and Deepgram were not.
- **Config defaults.** `LoadConfig` now decodes YAML over `DefaultConfig`; golden effective-config tests (`server/config_effective_test.go`) pin the shipped development and production files; `LoadConfigProfile` backs the `-profile` override. `turn.stop` must contain `speech-timeout`; the summarization key is `context.summarization` (agent config).
- **Start strategies:** `turn.min_words` selects MinWordsStart; push-to-talk (ExternalStart/ExternalStop) is opted into per call by the client.
- **No provider emits `ToolCallFrame`** (only the Whisker conformance harness does), so turn-completion tool-first leniency is tested only.
- **Parallel tools are wired**: `MaxParallel` is configurable via `agent.llm.max_parallel` and `server.tools.max_parallel` (defaults to 4).
- **TTS text filters are enabled**: `CleanTTSText` strips markdown, HTML/XML tags, and emojis before synthesis; opt-out per agent via `clean_text: false`.
- **Eager stop has no speculation gate** and no retraction; use only with punctuating STT.
- **Failover timing and residuals.** First-token watchdog `failover.llm_first_token` 8 s with fallbacks, total `failover.llm_budget` 60 s; Google and xAI STT open is 2 attempts of 5 s (Deepgram 3 x 5 s when it is the last candidate); non-last STT/TTS candidates get at most 2 attempts (STT opens capped at 5 s each). Still open: a primary that has started streaming is bounded only by the provider request timeout (30 s for the whole LLM stream, per round); reasoning models whose first token exceeds 8 s need a raised `llm_first_token`; the breaker can open after 5 watchdog cancels; a TTS cascade deeper than 3 finishing units loses the oldest unit's tail frames (stopped, usage, tail error). Deepgram and xAI STT export no counters.
- **Dead or library-only code**: `Session.DebugDropped` (no exporter), `ValidateToolPairing`, `AnalyzerStop` are unused by the server. `DefaultConfig` is now used by `LoadConfig`.
- **Summaries**: token usage not attributed, no output-token cap, no cooldown after a discarded summary.
- **Redaction**: DTMF digits reach the client's user-transcription frame and the LLM context by design; digit-run and IBAN rules are heuristics. Raw error text remains at `server/trace/adapter.go` (`error.category` attribute), `server/call.go` ("turn not recorded" log) and `server/recording.go` ("call recording not saved" log); Google STT `endTrace` only receives fixed strings today (checked), so that site is safe unless a caller changes.
- **Recording** is unencrypted at rest, taps audio before the filter chain (unfiltered inbound), a mid-call agent disable does not stop it, and no disclosure is played to the caller.
- **Unmeasured with real providers**: warm-up gain, real STT/LLM/TTS latency (baselines use fakes), smart-turn and completion quality, denoiser false-barge-in rate on noisy audio. Deepgram, Cartesia, ElevenLabs and generic OpenAI-compatible defaults come from docs and fakes, not live APIs (Google, Nvidia Riva STT/TTS and NIM, and xAI STT/TTS/LLM were run live, small n). Google gRPC burst-replay for STT failover is unverified.
- **Admission is reject-only**: no queueing or weighted fair share.
- **Capacity**: 384 sessions clean in the latest sweep on a busy laptop, one earlier run lost all workers to an unexplained stall; a residual in-flight paced frame can still delay a caller chunk; after T11 `ErrSlowOutput` can fire before `ErrSlowClient`. A 24 h soak is not planned (calls last 2 to 3 minutes). Churn evidence is one 90 s container run (68 calls, fake providers); a longer churn at real call lengths, and with real providers, is still open.
- **ONNX Runtime exit abort.** A rare abort at exit ("recursive_mutex lock failed") is attributed to ORT's telemetry thread racing static destructors. Telemetry is now disabled (`ORT_DISABLE_TELEMETRY=1`, set in `vad/silero.go` before the ORT env exists, passed to workers by `WorkerEnv`). `vad.ShutdownORT` runs after the ORT sessions close on the clean exit paths of `cmd/server`, `cmd/vadworker`, `cmd/turnworker` and the `vad` and `smartturn` test mains; it is skipped on `os.Exit`/`log.Fatal` error exits (worker handshake failures, server start failures) and in the `server` test binary, which loads Smart Turn in-process (`server/turn_stop_test.go`) without a TestMain; the cause is plausible but unproven, and the Linux build is unverified. Privacy note: ORT telemetry (uploads to a Microsoft endpoint) was found active in the VAD workers before this fix.
- **Perf gate**: baseline from an uncommitted tree, no git commit recorded; regeneration pending (G6).
- **Assumptions still unconfirmed** (goalpulse): extra vendors chosen without an answer to Q1; denoiser open-source first; recording storage local only.
- **Different Silero model file** from Pipecat's bundled one; VAD decisions are not compared.
- **Coverage of this matrix**: paired fixtures cover turn start/stop timing, mute, idle, DTMF aggregation, sentence splitting, interrupted-reply content and summarization cut points, each on one component with scripted frames. Tool-loop ordering, async tools, failover, VAD, filters, observability and operations rows are evidenced by go-voice tests only.

## Missing versus Pipecat (ranked)
