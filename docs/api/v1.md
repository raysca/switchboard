# Management API v1

The Server registers `/api/v1/*` only on the admin listener. The public listener keeps `/health` and `/ws`; it does not expose management routes. Versioned paths and JSON fields are stable within v1. Future incompatible changes use a new path version. Persistent agent routes are provided by `api.NewAgentsHandler` and are mounted by the V2 composition layer behind the existing management authentication boundary; the V1 config-driven server does not open a product database automatically.

Set `management.api_key_env` in deployment YAML (default from `DefaultConfig`: `GOVOICE_MANAGEMENT_API_KEY`) to the name of an environment variable containing a unique, random key of at least 32 bytes. Send `Authorization: Bearer <key>` over a protected admin listener. The key is hashed at startup and compared in constant time. If the environment variable is absent, management routes return 503. The key must differ from the voice signing secret. Deployment must protect the admin listener with TLS or an equivalent trusted proxy/network boundary. Existing admin diagnostics (`/health`, `/ready`, `/metrics`, `/debug/timeline`) retain their V1 listener behavior and are outside `/api/v1`.

Responses use `{ "data": ... }` on success. Errors use `{ "error": { "code": "...", "message": "...", "request_id": "..." } }`; `details` is optional. Every management response includes `X-Request-ID`; error IDs match the header. Responses set `Cache-Control: no-store`. Auth errors never echo credentials or request bodies. POST/PUT/PATCH accept only `application/json` (parameters such as charset allowed), one JSON object, known fields, and at most 64 KiB. List endpoints may use `limit` (default 50, range 1–100) and `offset` (default 0, nonnegative).

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/api/v1/server-config` | none | `data`: `profile`, `max_sessions`, `max_call_duration_seconds`, `voice_token_max_lifetime_seconds` |
| POST | `/api/v1/voice-tokens` | `{ "principal": "user-id", "pipeline": "default" }` | 201 `data`: `token`, `expires_at`, `scope` |
| GET | `/api/v1/agents` | optional `limit`, `offset` | `data`: agent array |
| POST | `/api/v1/agents` | `{ "name", "description", "enabled?", "config" }` | 201 `data`: created agent and current immutable version |
| GET | `/api/v1/agents/{id}` | none | `data`: agent, current version, readiness |
| PUT, PATCH | `/api/v1/agents/{id}` | optional mutable fields and/or replacement `config` | `data`: updated agent; changed config publishes the next immutable version |
| POST | `/api/v1/agents/{id}/archive` | none | `data`: `{ "archived": true }` |
| POST | `/api/v1/agents/{id}/duplicate` | optional `{ "name" }` | 201 `data`: new agent with a copied configuration |
| POST | `/api/v1/agents/import-v1` | `{ "legacy_name", "name", "description", "pipeline" }` | 201 `data`: imported agent |

Agent configuration must be a JSON object. Object keys are canonicalized before hashing; the lower-case SHA-256 hash covers only canonical configuration bytes. Each accepted config update creates the next contiguous version number atomically with mutable-field changes and never rewrites an earlier version. Readiness reasons are bounded safe codes (`missing_stt`, `missing_llm`, `missing_tts`, `disabled`, `archived`, `readiness_unavailable`, `external_dependency_unavailable`); they do not include config values. The `configured` state means only that the minimum voice-stack fields are present. The `ready` state is returned only when the host's injected provider/MCP readiness evaluator confirms external dependencies. V1 import copies the named V1 pipeline fields into the agent config; the old pipeline name is used for import validation and is not retained as runtime config.

The agent handler is constructed with the persistent `agent.Service` and must be mounted only after the outer handler has authenticated the management bearer key. Session runtime code calls `ResolveCurrent` when creating a session and persists the returned version ID and config hash; historical lookup uses `ResolveSession`, so later edits cannot change that session's configuration.

The server-config projection is read-only and excludes token signing keys, management keys, environment variable names, provider credentials, system prompts, and raw YAML. The voice-token request requires a 1–128 byte principal and an existing 1–128 byte pipeline name. Issued JWTs use HS256, the configured voice issuer/audience and effective key ID (`v1` when omitted in production), a random `jti`, `scope=voice:connect`, and a lifetime capped at 60 seconds and the configured maximum. JWT times use whole seconds; nonzero `token.max_lifetime` must be at least two seconds and issuance rounds down to a whole second to remain within that maximum. They are intended for the existing `/ws` admission flow, which consumes each `jti` once. A voice token cannot authenticate `/api/v1`; a management key cannot authenticate `/ws`.

Provider management routes are registered on the authenticated admin listener:

| Method and path | Purpose |
| --- | --- |
| `GET /api/v1/providers` | List stable provider metadata and supported capabilities. |
| `GET /api/v1/providers/credentials` | List masked credentials and validation state. |
| `POST /api/v1/providers/credentials` | Add `{ "provider": "google", "secret": "…" }`; the response contains only a masked suffix. |
| `GET /api/v1/providers/credentials/{id}` | Read the masked DTO; never returns plaintext. |
| `PUT /api/v1/providers/credentials/{id}` | Replace a secret; validation returns to `unvalidated`. |
| `DELETE /api/v1/providers/credentials/{id}` | Delete a credential. |
| `POST /api/v1/providers/credentials/{id}/validate` | Run an explicitly configured provider validator and report its state. |
| `POST /api/v1/providers/credentials/{id}/rotate` | Re-encrypt under the currently active credential key. |
| `GET /api/v1/providers/{provider}/discovery?capability=llm\|stt\|tts` | Return bounded, sorted and sanitized model/voice options. |

Provider persistence, encryption keys, validators and discovery adapters are injected by the host before serving. If provider management storage or an adapter is not configured, the endpoint returns a safe unavailable error; adding a credential does not imply a live provider validation. All success and error responses use the common no-store envelope and never echo submitted secrets or provider error text.

API-issued scoped tokens include a random `issuer_epoch` generated by their validator instance. Replacing that validator rejects every earlier scoped token even while it is unexpired, closing the in-memory replay-cache restart gap. A deployment with multiple Server replicas must route token issuance and the corresponding `/ws` admission to the same replica. Cross-replica use requires a shared replay/issuance service in a later task. Compatibility: the V1 WebSocket validator continues to accept its historical unscoped admission tokens, while rejecting any explicitly scoped token other than `voice:connect`. Operators can therefore migrate token issuers without breaking existing clients. Removing unscoped acceptance requires a separately coordinated protocol change. The currently configured voice signing key remains the signing key for both legacy and API-issued voice tokens; the management key is separate and never signs voice tokens.

`/api/v1` and noncanonical `/api/v1/...` paths return the same JSON error envelope with `X-Request-ID` and `Cache-Control: no-store`, without an automatic slash redirect. The body limit counts the full request body, including trailing whitespace and any second JSON value.
