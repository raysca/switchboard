# Management API v1

The Server registers `/api/v1/*` only on the admin listener. The public listener keeps `/health` and `/ws`; it does not expose management routes. Versioned paths and JSON fields are stable within v1. Future incompatible changes use a new path version. Persistent agent routes are provided by `api.NewAgentsHandler` and are mounted behind the existing management authentication boundary. The agent store is mandatory: the server refuses to start without `storage.dialect` (`sqlite` or `postgres`), the DSN in `GOVOICE_DATABASE_DSN` and the credential keyring in `GOVOICE_CREDENTIAL_KEYS` (`id:base64(32-byte key)[,id:...]`, first entry active). Calls run stored agents only; YAML `pipelines:` is rejected at startup.

Set `management.api_key_env` in deployment YAML (default from `DefaultConfig`: `GOVOICE_MANAGEMENT_API_KEY`) to the name of an environment variable containing a unique, random key of at least 32 bytes. Send `Authorization: Bearer <key>` over a protected admin listener. The key is hashed at startup and compared in constant time. If the environment variable is absent, management routes return 503. The key must differ from the voice signing secret. Deployment must protect the admin listener with TLS or an equivalent trusted proxy/network boundary. Existing admin diagnostics (`/health`, `/ready`, `/metrics`, `/debug/timeline`) retain their V1 listener behavior and are outside `/api/v1`.

Responses use `{ "data": ... }` on success. Errors use `{ "error": { "code": "...", "message": "...", "request_id": "..." } }`; `details` is optional. Every management response includes `X-Request-ID`; error IDs match the header. Responses set `Cache-Control: no-store`. Auth errors never echo credentials or request bodies. POST/PUT/PATCH accept only `application/json` (parameters such as charset allowed), one JSON object, known fields, and at most 64 KiB. List endpoints may use `limit` (default 50, range 1–100) and `offset` (default 0, nonnegative).

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/api/v1/server-config` | none | `data`: `profile`, `max_sessions`, `max_call_duration_seconds`, `voice_token_max_lifetime_seconds` |
| GET | `/api/v1/operations/status` | none | `data`: `uptime_seconds`, `started_at`, `profile`, `active_sessions`, `max_sessions`, `capacity_utilization`, `sessions_total`, `turns_total`, `errors_total`, `database`, `vad`, `health` |
| POST | `/api/v1/voice-tokens` | `{ "principal": "user-id", "agent_id": "<agent id>" }` | 201 `data`: `token`, `expires_at`, `scope`; 404 unknown agent; 409 `agent_not_ready` |
| GET | `/api/v1/agents` | optional `limit`, `offset` | `data`: agent array |
| POST | `/api/v1/agents` | `{ "name", "description", "enabled?", "config" }` | 201 `data`: created agent and current immutable version |
| GET | `/api/v1/agents/{id}` | none | `data`: agent, current version, readiness |
| PUT, PATCH | `/api/v1/agents/{id}` | optional mutable fields and/or replacement `config` | `data`: updated agent; changed config publishes the next immutable version |
| POST | `/api/v1/agents/{id}/archive` | none | `data`: `{ "archived": true }` |
| POST | `/api/v1/agents/{id}/duplicate` | optional `{ "name" }` | 201 `data`: new agent with a copied configuration |
| PUT | `/api/v1/agents/{id}/mcp-tools` | `{ "tools": [{ "mcp_server_id", "remote_name", "schema_hash", "required" }] }` | `data`: newly published immutable agent version; empty array removes all current selections |

Agent configuration must be a JSON object using schema v2. Unknown fields and wrong types are rejected. An agent is attached to a set of providers when it is created or updated: every stage must name a `provider` and a `credential_id` of an existing credential for that provider, otherwise the request fails with `400 agent_not_attached` listing the problems (`missing_stt`, `missing_credential_llm`, `invalid_credential_tts`, ...).

**Graph agents.** `config` may be a graph instead of a flat stage config: an agent whose nodes are agents of their own, joined by LLM-driven handoffs. A config with a top-level `nodes` key is a graph; anything else is the flat form, which keeps working unchanged and reads as a one-node graph.

```json
{
  "entry": "front",
  "nodes": [
    {"id": "front", "name": "Front desk", "config": {"stt": {...}, "llm": {...}, "tts": {...}}, "position": {"x": 0, "y": 0}},
    {"id": "sales", "name": "Sales", "tools": ["<mcp_server_id>/<remote_name>"], "config": {"llm": {...}, "tts": {...}}}
  ],
  "edges": [{"id": "e1", "from": "front", "to": "sales", "condition": "The caller wants pricing or to buy."}],
  "handoff_cue": {"name": "chime", "after_ms": 300}
}
```

Each node `config` is the flat stage config. Call-level settings (`stt`, `vad_stop_ms`, `stt_p99_ms`, `recording`, `context`, `async_tools`) belong to the `entry` node only; other nodes set `llm` and `tts`. Each edge becomes a `transfer_to_<node name>` tool on its source node whose description is the `condition`; calling it hands the call to the target node, keeping the conversation history. A node exposes only the MCP tools it lists in `tools`, a subset of the tools selected on the agent version. Limits: 8 nodes, 32 edges, node names unique after lower-casing, one edge per ordered node pair, 10 handoffs per call. Invalid graphs fail with `400 invalid_config`; a node whose provider or credential is not attached fails with `400 agent_not_attached` and the node id prefixed to the problem (`sales:missing_credential_llm`). A call pins the whole graph through its agent version, so republishing never changes a live call. `handoff_cue.name` refers to a server-configured sound (`audio.cues`).

```json
{
  "stt":     { "provider": "google", "model": "chirp_2", "language": "en-US", "credential_id": "<google credential id>" },
  "llm":     { "provider": "google", "model": "gemini-2.5-flash", "system_prompt": "...", "credential_id": "<google credential id>" },
  "tts":     { "provider": "google", "voice": "en-US-Chirp3-HD-Aoede", "credential_id": "<google credential id>" },
  "context": { "max_messages": 64, "max_tokens": 8000 }
}
```

`context` is optional; unset limits default to 20 messages and 4000 tokens, and `max_messages` must be at least 2 when set. Each stage needs a `provider`; `llm.model` is required, while `stt.model` and `tts.voice` fall back to the provider's defaults. `llm.system_prompt` is at most 32 KiB. There is no implicit credential: each stage uses exactly the credential it names. An attached credential cannot be deleted (`409 credential_in_use`); if it is marked `invalid`, readiness turns `not_ready`. Providers: `google` (STT, LLM, TTS) and `xai` (LLM; STT/TTS only in builds tagged `xaispeech`). `GET /api/v1/providers` lists what the running build supports.

Object keys are canonicalized before hashing; the lower-case SHA-256 hash covers only canonical configuration bytes. Each accepted config update creates the next contiguous version number atomically with mutable-field changes and never rewrites an earlier version. Readiness reasons are bounded safe codes and never include config values: `missing_stt`, `missing_llm`, `missing_tts`, `invalid_config`, `unknown_provider_<stage>`, `unsupported_provider_<stage>`, `missing_credential_<stage>`, `invalid_credential_<stage>`, `disabled`, `archived`, `readiness_unavailable`, where `<stage>` is `stt`, `llm` or `tts`. Only agents in `ready` or `ready_with_tool_warning` can take calls. There is no V1 pipeline import route.

Readiness includes bounded MCP states: `needs_tool_review` for schema drift/disappearance, `tool_dependency_unavailable` when a required server is disabled/unavailable, and `ready_with_tool_warning` when an optional selection is unavailable. These reasons never include config or tool values. The agent handler is constructed with the persistent `agent.Service` and must be mounted only after the outer handler has authenticated the management bearer key. Each call pins the agent's current version when it starts: it captures the selected MCP tools, persists a session row with the version ID and config hash, and ends that row on hang-up. Historical lookup uses `ResolveSession`, so later edits cannot change that session's configuration.

The server-config projection is read-only and excludes token signing keys, management keys, environment variable names, provider credentials, system prompts, and raw YAML. The voice-token request requires a 1–128 byte `principal` and a 1–128 byte `agent_id`. An unknown agent returns 404 `not_found`; an agent that cannot take calls returns 409 `agent_not_ready` with its readiness in `error.details`. The legacy `pipeline` field is rejected with 400 `invalid_request`. The token carries an `agent_id` claim; `/ws` has no `pipeline` query parameter. Issued JWTs use HS256, the configured voice issuer/audience and effective key ID (`v1` when omitted in production), a random `jti`, `scope=voice:connect`, and a lifetime capped at 60 seconds and the configured maximum. JWT times use whole seconds; nonzero `token.max_lifetime` must be at least two seconds and issuance rounds down to a whole second to remain within that maximum. They are intended for the existing `/ws` admission flow, which consumes each `jti` once. A voice token cannot authenticate `/api/v1`; a management key cannot authenticate `/ws`.

Provider management routes are registered on the authenticated admin listener:

| Method and path | Purpose |
| --- | --- |
| `GET /api/v1/providers` | List stable provider metadata and supported capabilities. |
| `GET /api/v1/providers/credentials` | List masked credentials and validation state. |
| `POST /api/v1/providers/credentials` | Add `{ "provider": "google", "secret": "…" }`; the response contains only a masked suffix. |
| `GET /api/v1/providers/credentials/{id}` | Read the masked DTO; never returns plaintext. |
| `PUT /api/v1/providers/credentials/{id}` | Replace a secret; validation returns to `unvalidated`. |
| `DELETE /api/v1/providers/credentials/{id}` | Delete a credential. Refused with `409 credential_in_use` while the current version of a non-archived agent is attached to it; `details` lists those agents (`agent_id`, `agent_name`). Re-attach or archive them first. |
| `POST /api/v1/providers/credentials/{id}/rotate` | Re-encrypt under the currently active credential key. |

Calls use these stored credentials; the server does not read `GOOGLE_API_KEY`, `GOOGLE_APPLICATION_CREDENTIALS` or `XAI_API_KEY`. A `google` secret is either an API key or a service-account JSON key (`"type": "service_account"`) sent as a JSON string; the JSON may be pretty-printed, while API keys must be a single token without whitespace. An `xai` secret is an API key. Credentials for provider `mcp` are bearer tokens for MCP servers only and cannot back an agent stage. Secrets are encrypted with the active keyring key. Adding a credential does not validate it against the provider; a bad secret shows up as a provider error on the first call. All success and error responses use the common no-store envelope and never echo submitted secrets or provider error text.

API-issued scoped tokens include a random `issuer_epoch` generated by their validator instance. Replacing that validator rejects every earlier scoped token even while it is unexpired, closing the in-memory replay-cache restart gap. A deployment with multiple Server replicas must route token issuance and the corresponding `/ws` admission to the same replica. Cross-replica use requires a shared replay/issuance service in a later task. Compatibility: the V1 WebSocket validator continues to accept its historical unscoped admission tokens, while rejecting any explicitly scoped token other than `voice:connect`. A call still needs an `agent_id` claim, so a token without one is admitted but the session fails to start. Operators can therefore migrate token issuers without breaking existing clients. Removing unscoped acceptance requires a separately coordinated protocol change. The currently configured voice signing key remains the signing key for both legacy and API-issued voice tokens; the management key is separate and never signs voice tokens.

`/api/v1` and noncanonical `/api/v1/...` paths return the same JSON error envelope with `X-Request-ID` and `Cache-Control: no-store`, without an automatic slash redirect. The body limit counts the full request body, including trailing whitespace and any second JSON value.
