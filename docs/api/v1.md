# Management API v1

The Server registers `/api/v1/*` only on the admin listener. The public listener keeps `/health` and `/ws`; it does not expose management routes. Versioned paths and JSON fields are stable within v1. Future incompatible changes use a new path version. No agent, provider, MCP, or history CRUD is implemented by this skeleton.

Set `management.api_key_env` in deployment YAML (default from `DefaultConfig`: `GOVOICE_MANAGEMENT_API_KEY`) to the name of an environment variable containing a unique, random key of at least 32 bytes. Send `Authorization: Bearer <key>` over a protected admin listener. The key is hashed at startup and compared in constant time. If the environment variable is absent, management routes return 503. The key must differ from the voice signing secret. Deployment must protect the admin listener with TLS or an equivalent trusted proxy/network boundary. Existing admin diagnostics (`/health`, `/ready`, `/metrics`, `/debug/timeline`) retain their V1 listener behavior and are outside `/api/v1`.

Responses use `{ "data": ... }` on success. Errors use `{ "error": { "code": "...", "message": "...", "request_id": "..." } }`; `details` is optional. Every management response includes `X-Request-ID`; error IDs match the header. Responses set `Cache-Control: no-store`. Auth errors never echo credentials or request bodies. POST accepts only `application/json` (parameters such as charset allowed), one JSON object, known fields, and at most 64 KiB. List endpoints may use `limit` (default 50, range 1–100) and `offset` (default 0, nonnegative); no list endpoint exists yet.

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/api/v1/server-config` | none | `data`: `profile`, `max_sessions`, `max_call_duration_seconds`, `voice_token_max_lifetime_seconds` |
| POST | `/api/v1/voice-tokens` | `{ "principal": "user-id", "pipeline": "default" }` | 201 `data`: `token`, `expires_at`, `scope` |

The server-config projection is read-only and excludes token signing keys, management keys, environment variable names, provider credentials, system prompts, and raw YAML. The voice-token request requires a 1–128 byte principal and an existing 1–128 byte pipeline name. Issued JWTs use HS256, the configured voice issuer/audience and key ID, a random `jti`, `scope=voice:connect`, and a lifetime capped at 60 seconds and the configured maximum. They are intended for the existing `/ws` admission flow, which consumes each `jti` once. A voice token cannot authenticate `/api/v1`; a management key cannot authenticate `/ws`.

Compatibility: the V1 WebSocket validator continues to accept its historical unscoped admission tokens, while rejecting any explicitly scoped token other than `voice:connect`. Operators can therefore migrate token issuers without breaking existing clients. Removing unscoped acceptance requires a separately coordinated protocol change. The currently configured voice signing key remains the signing key for both legacy and API-issued voice tokens; the management key is separate and never signs voice tokens.
