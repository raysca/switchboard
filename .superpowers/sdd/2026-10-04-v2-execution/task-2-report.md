Behavior: mute tags incoming audio at admission and discards it before processors, even when an unmute control overtakes queued media. Unmute resumes the same session. A posted flush advances the cancellation generation, so queued and late assistant text, TTS, and output audio from the old generation are discarded. Control frames and partial context events for previously delivered audio survive the fence. Explicitly uninterruptible output survives session and fake-transport flush; normal assistant output is interruptible by default. The existing V1 control queue policy is preserved.

Ruling: output disposition defaults to interruptible and must be explicit for critical audio — ordinary assistant output remains cancellable — cost if wrong: producers with critical media must add the disposition field. Ruling: mute takes effect at input admission while its state event is serialized through the control queue — prevents a queued unmute from releasing audio admitted during mute — cost if wrong: a caller expecting already-queued audio to be retroactively muted needs a separate queue-drain policy. Ruling: the typed `RuntimeSettingsUpdate` envelope is declared but not applied — respects P1 task ownership — cost if wrong: Task 27 may need an additive field or type migration after implementation detail is chosen. Ruling: partial assistant context events and explicitly uninterruptible output are exempt from the stale output filter — preserves evidence of audio already delivered and critical media — cost if wrong: a downstream adapter may need more precise delivery metadata.

Limitations: the P0 flush is server-side only; it cannot clear audio already buffered in an RTVI client. `TurnLifecycle` is a public one-shot state primitive; existing V1 `string`/`uint64` frame fields remain for compatibility, with wider typed runtime migration still pending.
